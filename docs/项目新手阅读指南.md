# 小咪小咪 miaoMi：项目新手阅读指南

本文对应 2026-09-30 的项目代码。你现在主要看的文件是 `apps/miniapp/pages/index/index.uvue`。

先记住三件事：页面负责显示和接收点击，游戏规则负责改变数值，存档负责把进度留到下次打开。

## 1. class 里面是什么，为什么 Ctrl + 左键没有跳转

例如页面开头：

```html
<view class="app-shell">
```

`app-shell` 叫 **CSS 类名，也叫样式类名**。相当于给这个元素贴一个标签，让 CSS 找到它并设置外观。它不是函数名，也不是保存猫咪数据的变量。

它对应的样式在同一个文件末尾的 `<style>` 中，目前是第 267 行：

```css
.app-shell {
  height: 100vh;
  display: flex;
  flex-direction: column;
  background: #f7f5ee;
  color: #465346;
  overflow: hidden;
}
```

代码中的 `class="app-shell"` 没有点，CSS 中的 `.app-shell` 有点。这个点表示“寻找具有这个类名的元素”。上面为阅读方便展开了格式，原文件的样式目前挤在一个长行中。

其他常见写法：

| 写法 | 通俗解释 |
| --- | --- |
| `class="card cat-details"` | 同一个元素用了 `card`、`cat-details` 两个类，空格分隔 |
| `.card` | 设置所有带有 `card` 类的元素 |
| `.choice.selected` | 设置同时带有 `choice` 和 `selected` 类的元素 |
| `.return-panel .primary` | 设置 `return-panel` 内部带有 `primary` 类的元素 |
| `:class="{ selected: newBreed == item.id }"` | 只有选中了这个品种，才加上 `selected` 类，显示选中外观 |

“按键点击能否跳转”是编辑器提供的功能，不是程序必须具备的功能。没有跳转，不等于这个样式无效。

- **HBuilderX 默认快捷键**：按住 `Alt` 再左键点击；也可以右键查看“转到定义”。切换过键位方案后，以编辑器显示的快捷键为准。[官方快捷键说明](https://hx.dcloud.net.cn/)
- **VS Code**：通常是 `Ctrl + 左键` 或 `F12`，前提是当前语言服务能找到定义。[官方说明](https://code.visualstudio.com/docs/editing/editingevolved)
- **VS Code 打开 `.uvue` / `.uts`**：在扩展面板搜索 DCloud 发布的“uni-app x语言服务”，安装后重启编辑器，检查文件类型是否识别为 `uvue` / `uts`。这能提供相应语言服务，但不保证每个 CSS 类名都能点击跳转。[DCloud 安装说明](https://doc.dcloud.net.cn/uni-app-x/tutorial/ls-plugin.html)

现在最直接的方法：在 `index.uvue` 里按 `Ctrl + F` 搜索 `.app-shell`。寻找其他文件中的样式时，用 `Ctrl + Shift + F` 搜索整个项目。动态类名也可以这样找，比如搜索 `.selected`。

## 2. 文件后缀代表什么

| 后缀 | 是什么 | 你可以怎样理解 |
| --- | --- | --- |
| `.uvue` | uni-app x 单文件组件 | 一个文件装着界面模板、UTS 功能代码、CSS 外观 |
| `.uts` | UTS 代码 | DCloud 的语言，写法接近 TypeScript；当前微信目标最终编译成 JavaScript |
| `.vue` | Vue 单文件组件 | 网页版使用，里面有模板、TypeScript 和 CSS |
| `.ts` | TypeScript | JavaScript 加上类型约束，例如规定 `food` 必须是数字 |
| `.js` | JavaScript | 执行功能逻辑；可能在网页、小程序或云函数中运行，要看所在目录 |
| `.mjs` | JavaScript 的模块文件 | 本项目用 Node.js 执行这些开发脚本 |
| `.html` | 网页文档 | 描述网页入口和页面结构 |
| `.css` | 样式文件 | 控制颜色、大小、间距、布局和动画 |
| `.json` | 数据或配置文件 | 用固定格式记录信息，不是业务逻辑代码 |
| `.md` | Markdown 文档 | 给人阅读的项目说明，不参与游戏运行 |
| `.svg` | XML 格式的矢量图片 | 本项目用作网页图标；网页猫咪组件中也有 SVG 图形 |
| `.cmd` | Windows 批处理脚本 | 双击执行一组命令，例如启动网页版 |
| `.wxml` / `.wxss` / `.wxs` | 微信模板 / 微信样式 / 微信辅助脚本 | 当前项目编译后生成，不是主要手写源码 |
| `.map` | 源码位置映射 | 帮调试器把编译后的错误对应回源文件 |
| `.png` | 图片 | 本项目中主要是测试截图 |

`<view>`、`<text>` 是小程序页面组件标签，写法像 HTML，但不是浏览器里的 `<div>`、`<span>`。`.uvue` 也不能当作普通 HTML 双击运行。

## 3. 先认识项目的两套界面

项目现在有 **网页版和微信小程序版两套界面**，共用游戏规则。你在微信开发者工具中看到的是 `apps/miniapp/` 的界面。

```text
src/game/data.ts + engine.ts     手写的共用游戏数据和规则
            |
            +--> src/           网页界面，Vue 3 + TypeScript + Pinia
            |
            +--> 同步脚本生成 JavaScript
                       |
                       +--> apps/miniapp/common/game/       小程序调用
                       +--> 云函数 common/miao-game/        云端校验存档
```

因此修改 `src/App.vue` 不会直接改变微信页面；修改 `apps/miniapp/pages/index/index.uvue` 也不会直接改变网页版。

## 5. index.uvue 的三部分怎样读

```html
<template>
  <!-- 放什么元素、显示什么文字、点按钮调用谁 -->
</template>

<script setup lang="uts">
  // 保存数据，处理点击，调用游戏规则，读写存档
</script>

<style>
  /* 元素的颜色、大小、位置等 */
</style>
```

`setup` 是 Vue 的写法，表示这里的变量和函数能供模板使用。`lang="uts"` 表示脚本部分使用 UTS。

| 模板写法 | 通俗解释 |
| --- | --- |
| `{{ state.coins }}` | 把金币数字显示到页面 |
| `@click="care('pet')"` | 点击时执行 `care`，告诉它这次是抚摸 |
| `:breed="activeCat.breed"` | 把当前猫的品种传给猫咪组件；冒号表示读取变量的值 |
| `v-model="newCatName"` | 输入框和名字变量互相同步 |
| `v-for="cat in state.cats"` | 每只猫都显示一份内容 |
| `v-if="activeCat"` | 满足条件才创建这块界面 |
| `v-show="tab == 'home'"` | 界面保留，只控制显示或隐藏 |
| `:disabled="条件"` | 条件成立时禁用按钮 |
| `:style="{ width: activeCat.food + '%' }"` | 根据当前数值改变进度条宽度 |

## 6. 状态管理：猫的数值到底放在哪里

**“状态”就是游戏当前的情况。** 猫吃饱没有、金币多少、背包还有多少猫粮，都是状态。

整个游戏放在一个名为 `state` 的对象里。它的结构由 `src/game/engine.ts` 中的 `GameState` 规定。只看一部分，大概长这样：

```javascript
// 为讲解省略了其他字段，不是可直接导入的完整存档。
{
  coins: 200,
  cats: [
    { id: 'cat-1', name: '小橘', food: 75, water: 80, affection: 55 }
  ],
  activeCatId: 'cat-1',
  inventory: { food: 5, treat: 2 }
}
```

注意两个 `food` 不一样：`cats[0].food` 是这只猫的 **饱食度**；`inventory.food` 是背包里的 **猫粮数量**。饱食度越大越饱，0 最饿，100 最饱，不是“数值越高越饿”。

每只猫各有一份 `food`、`water`、`cleanliness`、`mood`、`energy`、`affection`，分别代表饱食、饮水、清洁、心情、精力、好感。创建猫时在 `addCat()` 中设置初始值。

### 小程序：ref 让 Vue 知道数据变了

首页目前第 69 行：

```typescript
const state = ref(engine.createInitialState())
```

`ref` 可以理解为“让 Vue 盯着这份数据”。它会让普通对象变成可被 Vue 观察的数据。只要其中的饱食度变了，使用这个数值的界面就会更新。

脚本中通过 `state.value` 取出实际对象；模板会自动处理这层包装，所以写 `state.cats`，不用写 `state.value.cats`。

`activeCat` 是根据 `activeCatId` 从猫咪列表中找出的当前猫，用 `computed()` 计算。它指向列表中的那只猫，不是额外复制一只猫，也不用再保存第二份饱食度。

当前小程序是 **首页的 `ref` 管理游戏状态，再传给子组件**，没有使用 Pinia 或 Vuex。子组件中的 `props` 是首页传下来的信息；`emit('change', ...)` 是通知首页“操作完成了，可以提示和保存”。

### 网页：Pinia 把状态集中起来

网页版的 `src/stores/game.ts` 使用 Pinia。可以理解为把各个网页组件共同使用的游戏状态放到一个公共位置。

```typescript
const state = ref(loadGame(localStorage) ?? createInitialState())
watch(state, () => {
  saveError.value = !saveGame(state.value, localStorage)
}, { deep: true })
```

第一行表示“优先读取存档，没有有效存档再创建新状态”。`watch` 表示“发现数据变化就执行保存”；`deep: true` 表示连 `cats` 列表里面的 `food` 变化也要观察。

**Pinia 本身没有自动替你保存到硬盘。** 本项目能保存，是因为另外写了 `watch` 和 `saveGame()`。

### 哪些数据只是临时界面状态

`tab` 表示现在看哪个栏目，`feedback` 是提示文字，`newCatName` 是还未提交的输入。这些也使用 `ref`，但它们不属于 `GameState`，不会随整份游戏存档保存。

职业小游戏里的答题选择、作文草稿、像素画草稿，目前也只是组件中的临时数据。切换栏目时可以保留在当前页面里，完全关闭重开后不会恢复这些草稿；回合信息和领奖记录会保存。

## 7. 点一次“喂食”，数据经过哪些步骤

```text
点击喂食按钮
    -> 首页 care('feed')
    -> 先补算经过的时间，再调用 engine.careForCat(...)
    -> 检查冷却、库存、猫是否在家等条件
    -> 扣猫粮，增加饱食度和好感，记录照料时间与日记
    -> Vue 自动更新数字和进度条
    -> 首页 persist() 保存整个游戏状态
```

实际代码位置：首页的 `care()`、`src/game/engine.ts` 的 `careForCat()`、`src/game/data.ts` 的 `CARE_ACTIONS`。

喂食配置为 `food +28`、`affection +4`，消耗一份猫粮。同种照料需要间隔 30 秒；性格喜欢这项照料时额外增加 1 点好感。已经很饱或猫粮用完时，规则会拒绝操作，不会照样扣库存。

忽略这几秒的时间流逝：初始饱食度 75，喂一次变为 `75 + 28 = 103`，再被限制为 100；猫粮从 5 份变成 4 份。限制在 0 到 100 之间由 `effects()` 中的 `clamp()` 处理。

界面使用 `Math.round()` 显示整数。内部会保留随时间变化产生的小数，所以显示暂时没变，不代表内部没有结算。

## 8. 时间、饥饿、离线是怎么计算的

项目没有让关闭的小程序一直在后台运行，而是保存 **上次结算时间 `lastUpdatedAt`**。

`advanceTime()` 计算“现在与上次相比过去了多少小时”，再按比例改变数值。当前每小时饱食度减少 3，饮水减少 4，清洁和心情各减少 1，精力恢复 4。

例如关掉前饱食度是 75，过两小时打开，忽略其他操作就是 `75 - 3 × 2 = 69`。离线最多补算 8 小时，长时间没回来不会无限扣。

小程序打开时每秒执行一次 `heartbeat()`，更新倒计时；普通游戏数值大约每 5 秒结算一次。不是每秒固定扣 3 点，而是按实际过去的时间计算。离开时停止这个定时器，回来再补算。

长期饱食或饮水不足才会扣好感，目前每只猫的忽视损失每天最多 6 点，单次离线也有限额。好感低于 20 会预警；低于 10，且在线预警经过至少 5 分钟，才会离家。离线返回会重新给出照料缓冲时间，外出后可免费找回。

## 9. 本地存储：退出后为什么还记得

**响应式状态负责当前页面，本地存储负责下次打开。** 这是两件事；只写 `ref`，完全关闭后数据仍会丢。

存档名称在 `src/game/data.ts`：

```javascript
export const STORAGE_KEY = 'miaomi.save.v1'
```

可以把它理解为一个固定的存档标签，每次保存用同一个标签替换上一份进度。

### 保存

小程序 `persist()` 中实际执行：

```javascript
uni.setStorageSync(STORAGE_KEY, engine.serializeGame(state.value))
```

`serializeGame()` 调用 `JSON.stringify()`，把对象转成 JSON 文本。`uni.setStorageSync()` 将文本写到当前设备的小程序本地存储。

保存的是猫咪、金币、背包、日记、未处理事件、陪伴起止时间、职业回合、照料冷却等整个 `GameState`，不是把 `index.uvue` 改写了，也不是在源码目录新建一个存档文件。

小程序在操作后保存，打开期间约每 15 秒自动保存，隐藏或关闭页面时也尝试结算并保存。失败会显示提示；无法读取的旧存档会先保留，避免直接用新进度覆盖。

网页版的 `saveGame()` 使用 `localStorage.setItem()` 保存同样的 JSON；Pinia 状态变化时通过前面的 `watch` 触发保存，页面隐藏时也保存。

### 读取

小程序 `onLoad()` 中：

```javascript
const raw = uni.getStorageSync(STORAGE_KEY)
const restored = engine.deserializeGame(raw)
if (restored) state.value = restored
```

这是从实际代码中抽出的主要步骤，原代码还有类型检查和异常处理。`deserializeGame()` 先用 `JSON.parse()` 还原对象，再检查版本、猫的数量、品种、数值和关联信息；无效存档不能直接拿来运行。

随后 `onShow()` 调用 `advance(true)` 补算离线时间。没有存档时先显示领养界面，确认领养后才保存新游戏。

### 本地存档和云存档有什么区别

| 本地存档 | 云存档 |
| --- | --- |
| 保存在当前设备、当前应用环境里 | 保存在你的 uniCloud 服务空间 |
| 不需要微信登录或联网就能玩 | 需要真实配置、云函数部署及微信身份校验 |
| 网页与小程序不会自动互相同步 | 部署后可通过设置页手动备份、恢复 |
| 清除存储、换设备等可能丢失 | 可用于恢复设备上的进度，并检查版本冲突 |

网页版的不同浏览器、不同地址或端口可能使用不同本地存档；微信模拟器和手机也各有自己的本地数据。可以通过项目的“复制存档备份 / 从剪贴板恢复”手动搬运，恢复前会备份原进度。

本地 JSON 可以被用户修改；存档校验能挡住坏格式，但不能证明金币是正常赚来的。当前云功能也主要是经过身份验证的备份，不是所有游戏操作由服务器计算。

## 10. 其他重点功能如何实现

| 功能 | 主要位置 | 通俗解释 |
| --- | --- | --- |
| 首次领养 | `createGame()`、`adoptCat()`、`addCat()` | 收集选择，随机性格，给猫建立一份初始数值；金币随机 180 到 240 |
| 隐藏性格 | `data.ts` 的 `PERSONALITIES`、`getCatMessage()` | 性格保存在数据里，不直接显示；通过台词、姿态和偏好体现，并非无法从本地存档查看 |
| 多猫 | `state.cats`、`activeCatId` | 一个列表存多只猫，用标识切换当前显示的猫，最多 4 只 |
| 猫咪外观 | `CatRoom.uvue`、网页猫咪组件 | 页面把品种、性格姿态、装扮传进组件，组件负责画出来 |
| 随机事件 | `rollEvent()`、`resolveEvent()` | 到时间后从符合性格和猫数量的事件中抽一个；点击选项改数值，再清除这个待处理事件 |
| 偶遇领养 | `maybeEncounter()`、`acceptEncounter()`、`dismissEncounter()` | 抽来源、品种和性别，按来源调整性格概率；接受时加入家庭并按需扣金币，拒绝也推进下次时间 |
| 陪伴计时 | `startCompanion()`、`finishCompanion()` | 记录开始和结束时刻，界面显示“结束时刻减现在”；重新打开也能判断是否完成，奖励只结算一次 |
| 职业小游戏 | `CareerGames`、评分函数、`submitCareerRound()` | 程序员核对答案；作家检查字数和主题词；画家比较 8×8 像素颜色与位置；计算金币并记录已领奖 |
| 商城与装扮 | `SHOP_ITEMS`、`buyItem()`、`equipOutfit()` | 检查钱够不够，扣金币、加库存，再给猫设置装扮标识；金币不是真实支付 |
| 日记 | `state.diary`、`log()` | 游戏动作成功后加一条记录，保留最近 60 条 |
| 健康提醒 | 首页 `heartbeat()`、`state.remindersEnabled` | 页面运行时到时间显示提醒；设置保存到存档，当前没有后台微信订阅消息 |
| 本地备份恢复 | `exportSave()`、`importSave()` | JSON 复制到剪贴板，恢复时校验并先备份当前进度 |
| 云备份 | 首页云函数调用、`miao-session`、`miao-save` | 云端确认微信身份，只读写该用户存档；存档版本落后时拒绝覆盖 |

## 11. 想改某个功能，先找哪个文件

| 想改什么 | 应修改的源码 |
| --- | --- |
| 微信页面文字、布局、按钮外观 | `apps/miniapp/pages/index/index.uvue` 的模板和样式 |
| 微信猫咪长相、房间、姿态 | `apps/miniapp/components/CatRoom.uvue` |

| 网页界面 | `src/App.vue`、`src/style.css` 和 `src/components/` |
| 猫品种、事件文案、商品价格、喂食加多少 | `src/game/data.ts` |
| 时间衰减、初始数值、离家条件、评分算法 | `src/game/engine.ts` |
| 小程序本地保存与读取时机 | `index.uvue` 的 `persist()` 和页面生命周期 |
| 网页状态与自动保存 | `src/stores/game.ts` |
| 云登录与云存档 | `uniCloud-aliyun/cloudfunctions/` 中的手写文件 |

修改共用规则后，在项目根目录运行：

```bash
npm run sync:game
```

这会更新小程序的 `common/game/*.js` 和云端的 `common/miao-game/*.js`。然后重新运行 HBuilderX 工程。云端规则变更还需要重新上传对应模块。

不要直接改这两处自动生成的 `.js`。`npm run build` 和 `npm test` 也会自动同步；单独从 HBuilderX 运行时，不会替你执行根目录同步命令。

学习顺序建议：先在 `index.uvue` 找到一个按钮和它的 `@click`，再找到同文件函数，看它调用的 `engine` 函数，最后对照 `data.ts` 的数值和 `persist()` 的存档。先追踪一次完整喂食流程，再扩展到事件、职业和云服务。
